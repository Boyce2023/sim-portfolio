# case: 铁律1的"披露日"口径三次踩坑 — 每次都给出反向结论

**日期**: 2026-08-26 ~ 2026-08-27
**类型**: 规则实现缺陷（非交易判断）
**严重度**: P0 — 三个bug各自都能让 BEAT/MISS 判反，而铁律1是买入和卖出的共同前置

---

## 铁律1原文（Buwen 2026-08-26 亲定）

> 如果财报出了但是跌了，那就是不及预期，不管之前披露的预期是什么，不重要。

规则本身极简：**只看价格投票，不看财报数字**。难点全在"从哪一根K线开始算"。

---

## 三个bug，全部出在"基准K线选哪根"

| # | bug | 后果 | 暴露案例 |
|---|---|---|---|
| 1 | 披露日之后零根bar时，走 `chg_todate=0.0`，`0<0` 为假 → 判 **BEAT** | **零数据被包装成"超预期"**，是最危险的一种假输出 | 恩捷/精达 08-25 刚披露 |
| 2 | 一律从披露日**收盘**起算 | A股公告分盘后发（反应在次日）和盘前发（反应就在披露日那根K线里）。盘前发的整根反应被漏掉，还会判反向 | 金盘科技 08-21 跳空+6.3%高开、收+12.9%、4.5倍量 → 旧版判 MISS -4.8%，真实是 BEAT +9.94% |
| 3 | 用实时价补当日bar时写成 `O=H=L=C=现价` | 合成bar造出**假跳空**，把"公告今晚发"误判成"盘前已发"，基准整体前移一天 | 概伦电子 08-27 真实开盘42.00（跳空-0.71%），合成bar让检测器算出+3.5%跳空 |

**bug 3 是修 bug 2 时引入的**——修复本身带进了新缺陷。

---

## 修法

1. 披露日后 `bars_after < 1` → `UNKNOWN`，绝不给 BEAT
2. 跳空判别：披露日 `|gap| ≥ 2%` 或（`|move| ≥ 5%` 且 `量 ≥ 前5日均量×2`）→ 反应已在当根，base 前移一天
3. 合成bar必须带**真实**开/高/低（从 `astock_data_layer` 实时行情取），不许 O=H=L=C
4. 新增 `PENDING`：披露后只有今天这根未收盘bar时不判 BEAT/MISS（盘中拉一下就判会给假结论）
5. 披露日撞非交易日（周末）顺延到之后第一个交易日

## 可迁移的教训

1. **"零数据"必须显式建模成第三种状态**，不能让它落进二元判断的任一边。任何 `if x < 0: MISS else: BEAT` 的结构，都要先问"x 有可能是空的吗"。
2. **修bug时引入的新bug最难发现**，因为注意力已经从"这个功能对不对"转到"我的修复生效了没"。bug 3 就是这么来的——我验证了"价格补上了"，没验证"补上的价格结构对不对"。
3. **规则口径的歧义要用市场机制去消解，不是用约定**。"披露日"本身不含盘前/盘后信息，但跳空+放量是可观测的，用它反推公告时点比查公告时间戳更可靠也更通用。
4. 与 [[case_output_is_not_working]] 同族：三个bug都**照常输出了一个看起来正常的 BEAT/MISS**，没有任何报错。
